# xDrive「系统依赖」UI v1.0 + HTTPS 8443 网络实施规格（冻结基线）

> 版本：v1.0 · 2026-10-20  
> 性质：用户批准的实施设计基线；与当前代码是否已实现严格区分。  
> 实施原则：先复核并收尾既有专项 PR，再按 AGENTS.md 的完整基线、唯一工作提交、准确 HEAD 全量 CI、清洁合并与分支收尾推进。  
> 生产边界：未取得独立生产变更批准与安全门禁前，不得修改实际 Caddy、DNS、路由器、证书、阿里云凭据或宿主配置。

## 1. 已确认事实与优先级

以下事实来自管理员现场反馈及现有源码/截图，除明确注明的本机检测外，不是自动化在真实客户环境取得的网络证据：

| 项目 | 确认事实 | 证据边界 |
| --- | --- | --- |
| 公网域名 | 外网通过 HTTPS 正常访问 | 用户报告，仍须独立测试 TLS 与管理员登录 |
| 局域网访问相同域名 | 超时 | 用户报告，不可直接断定 NAT Hairpin 是唯一根因 |
| 局域网私网 IP HTTPS | 可以打开，但地址栏标识不安全 | 不能推断仅由域名 SAN 导致，需核验 Caddy Local CA 客户端信任 |
| 公网宿主 HTTPS 端口 | **8443/TCP** | 最新确认值覆盖此前所有 443 假设 |
| Caddy 容器 HTTPS 端口 | 443/TCP | 属于容器内部监听，不应擅自改为 8443 |
| 客户端 | Windows、iOS Safari/PWA、Android 等都不修改 | 不安装/分发根 CA、不改本机 DNS、不绕过证书警告 |
| 路由器 | 无法方便修改 | 不把 NAT Hairpin 或修改路由器 DNS 作为必需交付前置 |
| 外部中继 | 明确不接受 | 不新增 VPS 代理、Cloudflare Tunnel、第三方反向代理 |
| HTTPS 入口 | 公网域名与局域网 IP 实际均启用 | 均保留；可信域名是日常主入口，IP 是备用 |
| 管理配置差异 | 实际 IP TLS 已观测成功，目标配置开关却关闭且地址为空 | 必须只读查明，不能悄悄修改数据库或宿主配置 |
| 管理员采纳基线 | 必须管理员明确确认 | 仅安全条件满足时生成新的目标修订与审计，绝非宿主 Apply |

优先顺序：P0 存量 PR/分支清理 → P0 本规格入库 → P0 Caddy 三导航与正确性 → P0 移动端与 Desktop 验收 → P1 只读网络拓扑验证 → P1 可行方案的单独授权 → P2 其他 10 项系统依赖推广 → P2 安全 Host Apply 闭环（安全条件未满足绝不开放）。

## 2. 新 UI 的产品合同

从“技术说明书式状态堆叠”改为“先给结果、再提供操作、最后按需展开技术证据”。

- 第一期只重新设计 Caddy / HTTPS 网关；抽取通用布局、状态/编辑/历史组件后依次推广至剩余 10 项系统依赖。
- 保留既定 xDrive 全屏 App Frame、**52px 全局应用标题栏**、ui/shared MUI、已部署 Server 和 Go Desktop Agent 路由。不得引入第二套并行后端或独立 iOS UI 实现。
- Caddy 详情顶级导航固定为 **概览 / 配置 / 历史**；禁止再默认同时展开三个大型 Accordion。其他依赖在迁移前保留既有合同。
- 服务名称只出现一个主标题；正常状态使用一行主结论，不同时重复“可用、正常、配置已完成、本机 TLS 已验证”等同义徽章。
- 一项事实只显示一次；对于安全边界，主屏一句简短说明，具体限制转移至对应证据或保存确认。
- 桌面正文最大宽度目标 1120px；手机单列稳定的 iOS 设置式分组表单，触控目标至少 44px，支持暗色、键盘、焦点、辅助阅读和安全区域。
- 路由原有 status / verify / config / history 深链接必须兼容映射：status、verify 进入概览（verify 定位检测详情），config 进入配置，history 进入历史。浏览器前进/后退、服务切换及未保存草稿离开确认照旧生效。
- 不显示没有真实后端执行能力的启停、Apply、Restart 按钮；只显示当前可执行并经过权限验证的操作。

## 3. 概览：先显示真状态

首屏依次为主运行摘要、两个 HTTPS 入口摘要、异常待办，最后才是“检测详情”和“安全预检”按需入口。

### 3.1 单一运行摘要

成功时显示“Caddy 网关运行正常”，副标题说明“本机公网域名与私网 IP HTTPS 已分别验证”，附最近一次检查时间和手动刷新。

- 运行健康只依赖新鲜、可信的 Host Control / Docker 观测或具有明确限制的独立网络证据。
- 实际状态与目标修订是两种独立信息，不能因宿主健康而声称目标配置已经应用。
- 如果 Host Control 快照缺失，保留精确原因和独立 TLS/内部 HTTP 证据，不得假报宿主健康。
- 若旧 Server/Agent 无新字段，显示“未取得证据”，不可猜测成功。

### 3.2 两个入口摘要

**公网域名 HTTPS（主入口）**：显示来自可信管理配置的域名、宿主 8443 端口、服务器本机 TLS 及证书域名校验；局域网可达、公网可达分别给状态和证据来源。公网可达来自用户报告时明确标“用户反馈”；没有真实独立探针不得当作系统检测成功。

**局域网 IP HTTPS（备用入口）**：显示可信宿主观察到的 IP、宿主 8443 端口、Local CA、IP SAN 和本机 TLS 验证；当前客户端及其他设备是否信任本地 CA，未知时永远标“未验证”。不能依据 Server 校验成功标记所有终端“安全”。

浏览器若提示证书不受信任，提供只读证书原因及按平台说明，不引导绕过警告输入管理员凭据。根据用户“不修改客户端”的选择，不能把分发 CA 作为默认解决方案。

### 3.3 证据、预检和异常

“检测详情”展示独立证据轴：宿主快照新鲜度、固定 Docker 容器健康、caddy:80 内部 Ready、caddy:443 系统 CA 域名 TLS、本机私网 IP Local CA/IP SAN、外网/内网实际可达、Admin 应用回执。每项有来源、采样时间、结论、失效标记，不将同一请求的弱证据提升为强证据。

“安全预检”保留已有七项受限只读检查与 AliDNS 只读权限检查，但默认仅给上次结果和查看入口；展开或切换标签本身不得触发写操作、配额型远程请求或宿主控制。

仅异常时显示待处理，例如“运行 IP HTTPS 已开启、管理目标为关闭”；提供“查看差异”，不可自动补写目标或改动 Host。

## 4. 配置：运行状态、目标配置、实际应用严格分开

配置页先展示简短的“当前运行（只读）”摘要，再展示“管理员目标配置”，最后是独立的 AliDNS 凭据管理。运行状态来自可信 Host 观测；目标来自 PostgreSQL 修订；应用结果必须是独立可信、修订绑定的 Host 回执。

### 4.1 两个 HTTPS 入口

- 公网域名和私网 IP 分别一行，默认只读显示运行/目标状态。
- 点击“编辑”才展示期望开关、地址输入框和字段校验。
- 两入口可以同时开启，不得把二者都设为关闭；需要同时做 UI、Server 及后续 Host Manager 的校验。
- 地址字段仅可编辑经过合同验证的公有域名和规范 RFC1918 IPv4，不允许 URL/路径、任意 IP 或静默升级 HTTP 入口。
- 只有草稿发生变更且验证通过时出现“保存目标配置”；未保存草稿阻止静默覆盖、隐式刷新、跨页切换。
- **保存目标配置只产生 DB 目标修订/审计，不更新 .env、不重启 Caddy、不签发或替换证书。**
- Caddy Apply 目前继续受控、尚不开放；主屏不显示不可点击的假“应用”按钮。

### 4.2 运行与数据库目标不一致

必须明确显示三种不同数据：

1. 真实运行：可信 Host Control 证明的 IP/域名入口与本机 TLS。
2. DB 目标：已保存的 enabled/domain/lan_enabled/lan_ip 及 revision/source。
3. 应用证据：是否有同一修订的可靠 Applied Receipt；没有即“未确认”，不能从相等或旧宿主导入倒推。

当前现场“IP HTTPS 运行有效，但 DB revision #1 的局域网目标开关关闭、地址为空”应列 P0 正确性：只读检查 Host Control 快照、运行 Server 的 XD_DOMAIN / XD_LAN_HTTPS_IP、导入策略、目标修订的源数据以及是否曾有管理员编辑。

现有导入仅在尚无 DB 管理记录时建立 revision #1，不得在 UI 上直接把观测状态覆盖目标。若提供“采纳当前宿主为管理基线”功能，必须具备可信新鲜快照、规范化与去敏、差异预览、修订 CAS、显式管理员确认、审计及错误回滚的数据库事务；仅新建目标版本，不触碰实际 Caddy、DNS、CA 或容器。一切条件未满足时仅显示差异及不能采纳的原因，不显示伪可用按钮。

### 4.3 AliDNS DNS-01

默认折叠为一条状态行，例如“AliDNS · 已加密保存 · 凭据修订 #1（旧宿主导入）”。点“管理”后进入独立编辑状态，才出现 AccessKey ID / Secret 替换、显式清除、临时查看。

- 保存时必须使用版本化加密与审计，空输入不能误清空现有凭据。
- 明文显示最多 30 秒，失焦、页面隐藏及关闭设置立刻清除内存中的可见值。
- “已经导入管理数据库”“原 Caddy 正在运行”“当前 DNS 读权限有效”“写 TXT 权限有效”“证书已成功签发”是不同事实，不能合并成“生效”。
- 禁止把旧宿主凭据导入成功描述为“已经应用管理员新修订”。

## 5. 历史：按需读取、差异预览

历史页单独展示按时间排序的修订、来源、操作者、时间、变更摘要。初次进入其他页面不得加载历史。

选择旧修订先查看字段差异；确认“恢复历史目标”只创建新的数据库期望修订与审计，绝不视为网关应用、证书更换或 DNS 更新。并发修订不一致时阻止写入，提示重新读取。

## 6. HTTPS 网络路径冻结（宿主 8443）

### 6.1 现有链路

公网：用户客户端 → 既有公网域名:8443 → 当前路由/NAT → xDrive 宿主 :8443 → 固定 Caddy 容器 :443 → Server :8080。

局域网 IP 备用：客户端 → LAN IPv4:8443 → 同一 Caddy :443；Caddy Local CA 证书可能不被设备信任。

这里区分**宿主 8443**和**容器内 443**；不应为了改访问 URL 而将 Caddy 容器端口也改为 8443。DNS A/AAAA 记录不负责配置 HTTPS 端口。AliDNS DNS-01 在现有公网证书配置下保留。

### 6.2 保留条件与禁止动作

- 公网域名外网已可用，不删除、不改名、不擅自变更证书/端口/公网 A/AAAA。
- 局域网原域名访问超时，不能无证据地宣称原因就是 NAT Hairpin；先区分 DNS 回答、IPv4/IPv6 优先级、路由与 TCP 握手。
- 不要求客户端安装 CA、改 DNS、改 hosts、开 VPN；不要求修改路由器，亦不部署第三方中继。
- 不直接把既有公网主域名 A 记录改成私网地址；可能破坏公网入口或被 DNS Rebinding 防护阻断。
- 不关闭证书校验、不回退不可信 HTTP、不在浏览器安全警告页建议直接输入管理员密码。

### 6.3 实施路线（条件门禁，不是已落地）

**NET-0（只读网络事实）：** 独立核验局域网与蜂窝网络对相同 FQDN:8443 的 DNS A/AAAA、TCP 握手、实际网络路径与正确 TLS SNI/CA；核对服务器 8443 监听和防火墙映射，保证对当前用户服务无破坏。无真实证据时保持“不可达／未验证”。

**NET-1（优先现有可信域名）：** 若确有无需路由器或终端配置变更的原生 IPv6 网络，先验证端到端 IPv6 路由、端口、防火墙、AAAA、证书和授权登录；只在完整网络验收后，经单独批准发布。不能先改 AAAA 再边试边修。

**NET-2（备选独立 LAN FQDN）：** 若存在能够在全部目标设备解析到 LAN IPv4 的可信路径，可评估独立子域名以公网 CA / DNS-01 签发域名证书并通过 LAN:8443 直连。必须验证 DNS Rebinding 防护、多平台 DNS 行为、HTTPS Host/SNI、Origin/Cookie/CSRF、Web/Desktop/iOS PWA 深链接和登录。单独子域名会产生新 Origin，不能假设与公网主域名完全等价；不能擅自操作阿里云生产 DNS。

**NET-3（条件均不满足）：** 保持公网域名外网可用、私网 IP HTTPS 备用，但如实展示客户端可能不信任本机 CA 的边界。不得承诺“全部设备无需改动即可安全 IP 登录”。必要时将“局域网可信主域名无客户端/路由器修改”标注为技术约束未满足，等待管理员允许新的网络条件。

所有 NET 阶段均为独立安全变更；**这份 UI 规格不授权 DNS、Caddy、宿主或路由器的真实修改。**

## 7. UI 状态文案对照（禁止虚假宣称）

| 已有证据 | 首屏应显示 | 绝不显示 |
| --- | --- | --- |
| Docker Healthy + 本机双入口 TLS Verified | 网关正常；本机双入口 TLS 已验证 | 全网所有终端安全、公网所有路径可达 |
| Host 快照缺失但 caddy:80 通过 | 内部代理有响应；宿主运行未确认 | Docker 已安装且健康 |
| caddy:443 公共 CA + Ready 通过 | 内部域名 HTTPS 验证通过 | WAN/路由器/NAT 验证通过 |
| Local CA/IP SAN 本机验证通过 | 本机 IP TLS 验证通过；终端信任未知 | Windows/iOS/Android 已信任 CA |
| DB 目标与宿主状态不一致 | 当前运行与期望配置存在差异 | 自动切换当前开关/已应用 |
| AliDNS 密文已导入 | 凭据已加密保存 | DNS 修改权和续期已验证 |
| 保存目标配置成功 | 目标修订已保存 | Caddy 已受控应用/重启成功 |
| 无可靠 Applied Receipt | 当前目标是否生效仍未确认 | 将修订 #1 或本机 TLS 自动认定为已应用 |

## 8. 交互稳定性与安全约束

- 状态刷新保留已挂载界面、当前滚动位置和草稿，不显示瞬时空白、虚假加载页或造成容器尺寸跳变的反馈。
- 首屏主要状态与操作均可 keyboard focus；用户点击检查时有明确只读/在线配额说明，且结果不得未经授权保存或应用。
- 草稿未保存时跨 tab、浏览器前进后退和进入历史恢复需有保护；凭据显示离开时必须立即隐藏。
- 应用能力继续保持 apply_supported=false；缺少真正独立 Rescue、可信审批和签名 Host CAS、AliDNS 安全交接、原子备份安装、进程外 watchdog 回滚、双入口真实 TLS/管理员登录及不可伪造 Applied Receipt 时不得启用。
- 任何 Caddy/HTTPS 管理动作均不能复用普通浏览器会话为 Docker/宿主高级权限。

## 9. 分阶段开发顺序、验收与回退

### P0-A：收尾旧 Caddy HTTPS 检测 PR
检查对应专项 PR 的真实失败日志、唯一 HEAD、与完整 master 的冲突。只修本 PR 的根因，其他源码 Git blob 不变。新 HEAD 全量 CI 与 Final Gate 全绿，fresh mergeable_state=clean 后才 Ready/Rebase Merge 并确认分支删除。

### P0-B：本规格入库与实施边界
将本文以 docs 下独立 Markdown 规范提交，AGENTS.md 仅增加新的完整附加指导，不重写旧记录。审计时区分“设计已冻结”“代码已合入”“生产已验收”三种状态。

### P0-C：Caddy 详情第一轮 UI
先做三段导航、主摘要和重复文案去重；确保概览/配置/历史真实操作、旧深链接、草稿保护与按需历史。只改共享 UI 与必要的原回归测试，不新增 Host Apply / DNS 写入能力。必须验证 Web/Desktop 两端。

### P0-D：运行/期望差异与 AliDNS 管理
梳理并测试现有 revision #1 旧宿主导入规则，先落实只读差异。安全采纳基线属于独立服务端工作，只有完成 CAS、权限、审计和实际运行来源校验才能开放操作；AliDNS 按需编辑不降低密文隐藏要求。

### P0-E：移动端与真实体验验收
在 iOS Safari/PWA、Android Chrome、Desktop、宽屏 Web 验证三页视觉/交互、键盘、焦点、暗色、慢网络、切换/刷新/撤销以及证书证据文案。真实设备未执行则明确记录 NOT RUN，不以 Jest/Node 源码测试替代。

### P1：只读 HTTPS 拓扑事实、按门禁开展可行性评估
先保留线上公网域名:8443 和已有 Caddy；只读核查有足够证据后才提出独立的 DNS/网络实施请求。不因 UI 测试通过而更改公网入口。

### P2：将验证过的 Caddy UI 模板推广至其他 10 项系统依赖
统一信息架构而不伪造“开启/停用”能力；原百度 Static/JSAPI4、GeoNames、Worker、PostgreSQL、存储、照片分析的具体真实检查与权限不变。

### 回归测试矩阵
- 编译：Go Linux/Windows、Web、Desktop Linux/Windows、真实 PostgreSQL API Race、Rootless、镜像/installer、单提交 Final Gate。
- 前端：所有 11 项不丢失、旧深链接、草稿保护、编辑确认、按需历史、错误/权限状态、敏感字段隐藏、状态证据不虚假提升。
- 领域：Caddy 双入口、禁双关、旧宿主导入、缺失快照、TLS 通过但 Host 未确认、目标与运行不一致、AliDNS 加密历史、独立只读 Caddy TLS 不推断公网。
- 物理：iOS PWA / Android / Desktop、8443、局域网连接超时和 IP 证书警告的真实重现与诊断。未实测就标注未实测。

## 10. 当前产品的完成判定
