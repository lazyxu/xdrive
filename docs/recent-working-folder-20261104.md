# xDrive「最近使用」= 最近工作文件夹（2026-11-04）

## 目标与现状

原实现将每一次成功 `navigateTo` / Back / Forward / Tab 切换产生的目标目录直接写入 `xd_file_recent_access`，层级导航会把所有父目录挤入“最近使用”。这个 API 同时被原生 iOS Viewer 用于“最近打开的文件”，不能直接改成仅支持文件夹。

## 实现策略

- **独立历史**：新增 `xd_file_recent_folder_access` 与 `GET/POST/DELETE /api/v1/file-recent-folders`；保留原 `/api/v1/file-recent` 和 iOS 已确认的文件打开行为。旧客户端的路径导航 Touch 只影响旧历史，不污染新列表。历史最多 64 个；侧边栏默认显示最近 8 个文件夹。
- **只记文件夹**：Server 只接受属主拥有、未删除、非根目录且 `Node.Type=dir` 的节点；用 `(OwnerID, NodeID)` 去重。仍通过 NodeID 实时生成重命名/移动后路径，账户隔离与删除/回收站过滤沿用原查询。
- **连续导航**：Workspace 只有目录列表加载/导航完成后才提出候选；前一个文件夹在 5 秒内被新导航覆盖则取消，只确认最后仍显示的目标文件夹。打开路径和展开目录树不会直接写历史。
- **实际文件操作**：文件被用户明确打开或 Quick Look 时，立即确认其 **所属文件夹**；Desktop 新建文件夹成功亦立即确认目标目录。独立 Viewer 后台资源预取、缩略图、自动同步不触发 Touch。
- **节流**：单一文件夹连续 60 秒内相同确认合并；转到其他目录后返回则按新的使用顺序更新。失败请求不视作成功，切换账号、窗口取消、隐藏页面时取消尚未确认的导航。
- **能力门禁**：Desktop Agent/Electron 新增 `file-recent-folders` capability 和独立 IPC。旧版 Agent 不暴露此能力时不尝试新 API。浏览器直接使用新 REST。
- **最近文件**：iOS 仍走原 `/file-recent` 接口；不会迁移旧的目录访问记录到新表（旧记录大多是无意义的经过节点）。新版首次使用时文件夹列表可以为空，由真实后续活动逐渐填充。
- **清空**：只删除对应账户的文件夹历史，绝不删除 Node、CAS 文件或 iOS 最近文件历史。收藏独立，不受影响。

## 验收场景

1. 进入 `工作→科研→项目A`，每一级间隔小于 5 秒，最后停留 5 秒：只有 `项目A` 新增。
2. 在 `项目A` 打开文件：立即确认 `项目A`，连续操作不重复创建行。
3. 通过搜索打开文件：确认文件真正所在目录，而不是当前搜索上下文目录。
4. 切换账号/隐藏页面/卸载浏览器：取消尚未确认的目录，不把旧账号的挂起事件写到新账号。
5. 文件夹移动、重命名、删除、恢复：同一 NodeID 显示实时路径；删除后隐藏，恢复后不人为置顶。
6. 用旧客户端 Touch 文件夹：不能污染新的文件夹列表；iOS Viewer Touch 文件的行为保持。
7. 真实权限失败、非法 File Node、根目录：不改变文件夹历史。
8. `FileExplorerRecentController` 前 8 个与 Server 历史 64 个保持数量边界，查询按 `last_accessed_at` 排序。

## 后续非阻塞项

跨设备后台自动同步不写历史。更广泛的文件写入成功事件（批量移动、删除、上传完成）可在其真实成功回执位置进一步绑定目录确认；不能在“打开新建对话框”“选择待上传文件”之类的意图阶段提前写入使用历史。
