# xDrive「系统依赖」内部服务密钥自动托管规范 v1.0

**产品决策：2026-10-19 · 永久约束 · 当前为已确认的目标规范，不代表运行时已交付。**

本规范适用于所有由 xDrive **自己生成并持有**的内部加密、签名、会话及服务间身份密钥，并约束 Web、Mobile Web/PWA、Desktop 共同使用的管理员「系统依赖」页面、Server、安装器、升级器、Host Manager 以及未来相关服务。用户无需懂 Ed25519、编译 Go 或操作密钥文件。

## 1. 必须实现的默认用户体验

1. **自动初始化**：新实例在安全持久化存储和加密根密钥已就绪时，由可信 Server/安装器首次自动使用操作系统 CSPRNG 生成所需内部密钥。不能要求普通部署者运行 OpenSSL、复制 PEM/Base64、填写额外内部密钥、修改源码常量或手动重建镜像。按需初始化亦须自动且幂等；允许管理员只读查看，不把「生成」按钮当作常规部署前置步骤。
2. **自动持久化**：密钥按不同服务与用途隔离，使用经鉴别的服务端加密和版本化持久存储（优先复用现有 ConnectorSecrets/keyring 或经过独立评审的 Host/KMS 保护）。私钥、Cookie 密钥及等效凭据不能保存在前端、源码、普通配置 JSON、Git、CI 工件或日志。公钥可以展示安全指纹，但不得公开私钥。根加密材料本身由安装器受保护地持久配置，不能靠同一数据库内的明文自加密来冒充保护。
3. **跨升级稳定**：Server 重新启动、容器重建、镜像升级、迁移和备份恢复必须沿用原密钥、用途和修订；禁止每次启动生成新密钥，禁止在重新部署时覆盖历史密文或导致既有会话/签名/同步配置无意失效。
4. **多副本同一身份**：同一个 xDrive 实例的所有有效 Server 副本读取同一受保护持久版本；首次生成采用事务唯一约束／数据库锁或等价单主协调，阻止并发启动生成不同密钥。各副本必须检测 key ID、revision 与解密能力，绝不能按容器分别生成或用内存变量冒充实例密钥。
5. **丢失故障关闭**：仅在经可信记录确认「从未初始化」时才允许自动初始化。已有密钥而数据库、密钥环、备份或解密链路丢失/损坏时，必须显示「需恢复／不可用」，拒绝依赖该密钥的敏感操作，不得悄悄重新生成、回退到示例值或把未知当健康；提供可审计的恢复方案。
6. **最小权限和隔离**：仅受信 Server/Host 侧可解封私钥，前端与 Agent 只获取有限只读元数据或明确授权的操作结果；每服务分别设置用途、TTL、撤销范围与访问权限。任何管理员按钮不直接返回私钥，不生成可供普通用户使用的开放签名接口。
7. **管理员管理状态及轮换**：「系统依赖 → 对应服务 → 配置与修改／状态与检测」统一显示是否已托管、来源、key ID/非敏感公钥指纹、创建/轮换时间、revision、当前副本验证及生效/阻断原因。日常操作只有只读检查和开启/关闭业务意图。必要时提供管理员二次确认的「轮换密钥」，包含影响提示、版本 CAS、持久审计、备份/恢复和明确的会话/令牌撤销。只有旧密钥安全处理完毕才可把轮换标记为成功。
8. **明确区分事实**：「密钥已生成」「密钥可解密」「服务期望启用」「已获运行授权」「外部服务健康」「三端验收通过」是不同状态。保存或轮换成功不能伪造健康、许可或真实运行结果。未检测和未知始终不等于健康。

## 2. 范围边界：内部密钥不等于外部凭据

- **xDrive 内部管理**：例如 JSAPI 4.0 发布签名密钥对、地图专用 Cookie/session 加密密钥、未来由 xDrive 生成的服务内部签名根或 HMAC 密钥，适用自动生成、保存、生命周期及诊断。
- **第三方颁发或用户掌握**：百度 Static Map **Server AK**、百度 JSAPI 4.0 **Browser AK**、AliDNS 凭据、外部 OAuth 授权、上游 API Key、第三方证书/许可等仍按其供应方流程获取；xDrive 只能安全保存和检测，不能伪称自动生成了有效供应商授权。
- 如部署架构使用独立 KMS/HSM、宿主平台托管根凭据或企业外部信任根，允许自动检测和受保护初始化/接入，但不得通过修改 Go 源码实现日常配置，也不得以自行生成密钥取代必要的外部信任、批准或许可。

## 3. 百度 JSAPI 4.0 的专项约束

- 当前实现的 `jsapi4PinnedProductionPublicKey = ""` 是开发阶段的硬关闭门禁，不得要求普通管理员修改它才能开启地图。**后续实现须将实例内部签名密钥的生成和持久化从源码常量迁移到可信部署/Server 托管能力**，包含跨副本可信绑定、轮换及审计。
- **自动生成签名密钥不代表获得正式发布授权。** 如果需要独立审核者的放行证明，运营者自行生成的密钥不能充当该审核者：发布批准须通过与业务管理开关隔离的受信审批/签名链路，绑定已审查的 Server 构建、固定资源策略、HTTPS Origin、Browser AK 修订与撤销 epoch。不得允许管理员凭自己生成的钥匙签署任意未审核资源然后自我放行。
- 动态地图仍依赖真实合法许可、逐条审查的百度 JS/tiles/font/WASM 子资源合同与白名单、AK 泄漏审计、完整真实 Browser + Server upstream HAR、Owner 会话/配额/CSP/Electron 隔离及真实三端验收。现有 `reviewedJSAPI4ChildResourceCount = 0` 和未安装的可信发布保持 **NO-GO**，密钥初始化不得修改它们、不得使 `runtime_enabled=true`、不得试探外部脚本。
- 已保存的 Server AK、Browser AK 与 HTTPS 配置不因内部密钥初始化或轮换而清除、展示或重填；静态地图保持独立可用。

## 4. 界面与 API 合同（目标，不是既有 API 声明）

- 页面使用现有三段式单页布局：「状态与检测」「配置与修改」「历史与回滚」，Web/Mobile Web/PWA/Desktop 共用 MUI 组件和 Server 安全 API；不重复渲染凭据编辑器。
- 状态应区分 `not-initialized`（仅确实从未创建）、`managed`、`unavailable`、`needs-recovery`、`rotating` 等；仅返回脱敏的 `configured`、`source`、`revision`、`fingerprint`、`created_at`、`rotated_at`、`requires_restart`、`activation_state` 及结构化阻断原因。字段与端点需在实现 PR 中定稿，而非通过文档宣称已存在。
- 轮换必须有管理员鉴权、CSRF/重放保护、旧 revision 乐观锁或等价事务 CAS、二次确认、脱敏审计、限流，以及立即撤销或文档化的严格过渡/过期边界。禁止用页面点击直接安装未审核的 JSAPI4 release。
- 无法连接可信服务端/旧 Server 不支持时，显示「能力不可用／版本不兼容」，而不是伪造新密钥或弹出要求修改源代码的操作说明。

## 5. 验收矩阵与实施顺序

在声明已实现之前必须分别验证：

1. 全新安装自动初始化成功；重复初始化幂等且密文持久；敏感私钥不可通过任何普通 GET、错误、审计或浏览器 DevTools 获取。
2. 同一实例两副本同时启动与并发首次初始化：唯一密钥身份、唯一有效修订、两副本读取一致且不重复签发。
3. Server 重启、重新拉取镜像、升级、回滚与备份恢复后 key ID/指纹不变；安装器不擦除服务密钥；对旧配置有明确迁移策略。
4. 丢失/错误加密根、损坏密文、数据库异常、跨副本不一致：返回明确非健康状态，敏感服务故障关闭而其他无关服务不被破坏。
5. 非管理员、过期会话、重复提交、旧 revision、审计失败与轮换并发均拒绝；轮换后原 session/签名按定义失效，备份与恢复记录可核验。
6. 仅生成/轮换内部签名密钥并不改变 JSAPI4 `runtime_enabled=false`，不能代理未审查资源，Static Map 不被中断；获得独立真实放行证据后再单独进行端到端许可/网络/三端验收。
7. Go/PostgreSQL 原始集成测试、Web/Desktop 共享契约测试、安装/升级/恢复测试以及准确工作 HEAD 的完整 CI、Final Gate 和真机验证明确区分；无实测不得写「生产已就绪」。

**实施分期**：先固定本产品合同（本文件与 `AGENTS.md`）；随后分别交付（A）受保护、持久、实例级密钥生命周期及自动初始化，（B）只读状态/管理员受审计轮换，（C）百度 JSAPI4 受信发布链路与独立资源/许可验收。每一阶段各自验收；**本规范合入不会自动改变当前运行时代码或授权状态**。
