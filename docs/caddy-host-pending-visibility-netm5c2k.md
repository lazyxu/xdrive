# NET-M5-C2-K · Surface sticky pending Host reservation without leaking plans

After #2149 NET-M5-C2-J joined master, the PostgreSQL write-side edit fence correctly returns HTTP 409 to prevent desired IP/domain, HTTPS historical rollback, or encrypted AliDNS edits during a durable `pending-unapplied` operation. Before this change, both read endpoints still labeled edits available, so shared Web/Mobile Web/PWA/Desktop forms invited an operation that the Server would reject.

This stage adds one strictly read-only existence query of the fixed Host DB reservation to each ADMIN Caddy HTTPS/AliDNS config response: `host_apply_pending: boolean`. Pending returns `editable=false`, an explicit static explanation, and continues to return `apply_supported=false`. Neither response exposes the operator nonce, signature, plan, stage, credential material, IP/domain values from the pending row, or a trusted apply receipt. Missing reservation schema, database connectivity or query errors return 503 (do not falsely enable editors).

The two existing shared panels honor `editable=false` for save, history rollback, credential rotate/clear, and their action handlers; they display an accurate operator-reconciliation warning, distinct from a missing encryption keyring. Optional TS fields keep older Server/Agent compatibility; on stale clients the DB transactional fence from #2149 remains authoritative. Current revision and readonly status/history remain accessible. No route or Host process-control capability is added.

Real PostgreSQL authenticated two-Server integration covers the existing sticky reservation plus both read endpoints; a mounted Desktop source-contract regression covers the one shared UI consumed by Web and Desktop. No physical xDrive deployment was modified or restarted. The independent approved operator, Host/DB CAS, secure AliDNS handoff, primary-down Rescue, Caddy-only bounded restart, detached watchdog, enabled/disabled off-host TLS+admin login and immutable signed Applied Receipt remain NOT DONE. Production must continue to report `apply_supported=false` / `restricted-apply=blocked`.
