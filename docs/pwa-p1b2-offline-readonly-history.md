2026-10-22. Builds **only** upon P1-A and P1-B0 merged to master and P1-B1 explicit consent/first authorized range in the parent Draft PR #2306. P1-C gallery collections and P2 media-thumbnail offline caches remain out of scope.

## Product / trust boundary

- Public Service Worker App Shell remains public-only. The B2 browser is a *separate* hash route `#/offline/files`, intentionally outside the account FileExplorer and public Share capability. Keep the existing compact 52px header, shared Web/Mobile Web React entry, and all existing file/gallery/transfer interactions.
- Consent must be explicitly enabled while online using authenticated /me. On consent, write a **non-secret owner-scope locator** in the **same IndexedDB transaction** as that Owner's consent record. The hint records only origin, durable PostgreSQL installation UUID, user ID, username, and timestamp. It never stores JWT, refresh token, cookies, API URLs, tickets, file bytes or a fresh-auth claim.
- On a new browser process with no verified session, the user can **explicitly** open the bounded snapshot viewer. The hint is NOT an authentication credential. Always display a non-dismissable **historical, unverified, partial, readonly** warning and the shared-device privacy caution already present in Settings. File rows are static text: no download, preview, upload, creation, share or mutation.
- Maximum 10 directories, first 20 metadata items each (total <=200), 192 KiB/account for the existing canonical record, maximum age 7 days. Read-time normalization also refuses over-limit/local-corrupt object fields. No entire 100k scan on boot, no background access to media, CacheStorage remains public-only.
- Logout and account/instance mismatch clear private IndexedDB data; turning off consent removes its locator and Owner-scoped record. Best-effort BroadcastChannel invalidates already open historical views, without transmitting names/IDs/secrets.
- Fresh /me **must** match instance UUID + Owner ID + username and password-change status. After that, a separate Owner-controlled node GET and bounded 1-item child Range are required to recheck the **selected** folder ACL; a 401/403/404 or identity mismatch clears the stored metadata. No disconnected data ever becomes the authoritative online FileExplorer list. A transport outage preserves the *historical only* label. No ongoing transfers are switched, paused or interrupted by a SW update.
- Reconnect is event-driven, no polling; the selected folder alone is checked. Stale `/me`, directory GET and one-row Range HTTP work all accept the **same AbortSignal** and cancel immediately on view/scope change, allowing Go Request.Context cancellation without waiting for a full response. This is a backward-compatible optional signal addition to existing `XDriveApi.me/node`; source tests assert all three signals. Entry to the standalone historical view is blocked while browser-owned foreground uploads/downloads are active, including direct hash navigation, so a FileManager unmount cannot interrupt them. The original Files/Gallery Go Context cancellation baseline remains a separate, already merged performance test.
