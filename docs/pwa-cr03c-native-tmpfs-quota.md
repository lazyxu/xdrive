# CR03c: real browser IndexedDB quota through bounded OS scratch filesystem

Follow-up to issue #2348, after #2361 proved that CDP `Storage.overrideQuotaForOrigin` can report 1024 bytes while four 16MiB IDB transactions all commit. This PR does **not** count that fake accounting as real quota rejection.

The isolated CI Runner mounts a writable 2GiB `tmpfs`, starts actual Chrome with its Profile/IndexedDB on this mounted filesystem and captures one explicitly consented synthetic historic directory using production `pwaOfflineDirectory.ts`. A test-only Node process consumes physical free capacity on the same mount after the original commit. It then attempts a genuine 8MiB browser `IDBTransaction`; **only an actual native `QuotaExceededError`** is acceptable for the quota-specific acceptance. An OS `UnknownError` or arbitrary abort is correctly RED and not relabelled. The original production capture must reject the replacement and a subsequent historical-only read must not resurrect or replace old data. Public Service Worker CacheStorage stays public-only, and no production user/JWT/private file is used.

This test is exploratory until its exact HEAD authentic Chrome specialty and full 77-job cross-platform CI/Final Gate pass. A RED can indicate Chrome maps filesystem `ENOSPC` to `UnknownError`; it is not in itself evidence of a product bug. It must then be corrected using a real browser quota-enforcing runner, never by synthesizing a JavaScript `DOMException`. The unrelated actual Go Owner ACL is independently covered by #2349/#2378. Real device iOS/Android remains NOT RUN. Production-only inaccessible security acceptance 按用户决定跳过（未验收）. No change to Go, SW, browser upload protocol, historical public assets, private Blob cache, or AGENTS.

**First real run #39777663706:** authentic Chrome started inside tmpfs, the OS-level fixture filled 158,302,208 bytes and left only 65,536 bytes free, but the browser did not provide a confirmed native QuotaExceededError; this is RED, not a test pass or a production bug conclusion. The next revision records only the sanitized native error *name*, verifies whether the P1 write rejects under this real disk fault, removes disposable ballast, and confirms that the original persisted historical record has not changed. It retains a hard RED unless the browser really reports QuotaExceededError; native OS disk-full fail-closed and the specific quota exception remain separate outcomes.


**Revised experimental approach, 2026-10-22:** The old physical-pressure-only run [#39786741655](https://github.com/lazyxu/xdrive/actions/runs/39786741655) returned **native `DataError`**, not `QuotaExceededError`; its private anonymous artifact recorded `nativeWriteRejected=true`, `productRejected=false`, `oldHistoryIntact=false`. Because a smaller transaction may legitimately commit with some free LevelDB pages, that experiment does **not** prove a product quota bug or a quota pass. The test now prefers actual Chromium **Origin quota manager** rejection: it commits bounded real IndexedDB data at 8MiB→1MiB→64KiB→1KiB granularity and refuses to consume the final 32MiB of the OS tmpfs. Any `UnknownError`, `DataError`, lack of enforced quota, product write accepted, or stale/partial historical record remains a **RED**, never a synthetic JS DOMException or silently lowered gate. The native error name and quota-estimate byte count are only anonymous diagnostics. This is still subject to a fresh exact-HEAD real Chrome specialty + full CI; until both pass, **real QuotaExceeded is NOT VERIFIED**.


### 2026-10-22 native Chrome first RED and corrected physical load

Original accurate HEAD `b3845b44` [real Chrome CI #39794060000](https://github.com/lazyxu/xdrive/actions/runs/39794060000) correctly FAILED. Its anonymous artifact reported `OriginQuotaNotReached` after 22 × 8MiB zero-filled IndexedDB transactions all committed. Chromium returned estimated Origin quota 1,076,308,469 bytes, but the private 160MiB tmpfs still had 151,003,136 bytes free. Zero buffers were not sufficient to prove physical quota pressure; this is not a product P1 fail-closed result.

The revised probe uses browser `crypto.getRandomValues` high-entropy synthetic buffers, a 2GiB isolated tmpfs with ≥32MiB OS headroom, real statfs allocated-byte measurements, and a bounded 8MiB→1MiB→64KiB→1KiB descent. The acceptance still requires the native browser to throw precisely `QuotaExceededError`, reject the attempted bounded P1 overwrite and preserve its prior snapshot; `UnknownError`, physical ENOSPC or inability to reach quota remain RED. This is intentionally a nonproduction isolated test, with no credentials, real media, persistent private caches or automatic hashed asset deletion.
