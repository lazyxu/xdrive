# 传输记录：在云端文件管理器中显示（2026-10-10）

## 范围和状态

状态：**实现候选，待 exact-head CI / 真机验收**。

本轮先接通右键菜单的云端位置定位，不为本地路径制造不可执行的按钮。
Header 的共享 `XDriveTransferPopover` 是 Web/Mobile Web 与 Desktop 的
共同入口。支持定位的单文件任务右键可执行「在云端文件管理器中显示」，
直接进入既有 Files 应用和共享虚拟列表，不新建文件管理器后端。

- Web：单文件上传记录保存已认证的云端 `parent_id`；单文件下载
  （浏览器原生发送监控或应用自身流式接收）保存 Node ID / Parent ID。
  目录导航仍由 Server 执行当前用户授权。不能把 `file_name` 或 `path`
  当作云端目录，也不能从文件名推断父目录。
- Desktop：Agent 直接上传保存真实目标 Parent ID；直接下载保存真实 Node ID。
  右键时通过已有认证 Agent `nodeLocation` 解析可信的面包屑，再调用
  当前共享 FileExplorer 控制器的 `loadCloudDirectory`。
- 原先已存的 Web 历史、没有云端身份的文件夹或 ZIP 聚合任务、无法解析的
  来源任务：**不显示无法执行的菜单项**，并不假装它们可以定位。
  文件夹子任务/归档多来源尚未覆盖，会单独补充真实的逐文件身份。
- Mobile Web 继续共享相同数据和菜单组件，但触屏独立的“更多”入口及真机
  交互仍需验收；当前明确交付的是鼠标右键入口。
- 暂不提供“打开本地位置”：浏览器不得访问任意本机路径，Desktop 已有的
  `openPath` 只允许托管挂载目录，不能冒用它来打开任意上传路径。
  后续需通过 Agent 所拥有任务 ID 和经过校验的目标路径实现受限定位。
- 暂不提供假的暂停/继续。取消必须绑定真实网络/Agent 执行上下文，并明确
  浏览器原生下载接管后无法由当前 Popover 控制的边界。

测试：Go 传输快照序列化测试；Web/Desktop 适配器与共享上下文菜单的合同测试。
合并门槛：单工作提交、Web/Desktop 构建、Desktop/Go 相关测试、Windows
安装/升级回滚和 `final-gate` 全绿。物理设备验证另行记录。

## 2026-10-10 · Desktop Agent 受限的本地位置定位

Desktop 在传输右键菜单增加「在本地文件管理器中显示」，**仅对 Agent
真正创建的直接单文件上传/下载任务开放**。Client/Renderer 只提交
`transfer_id`，本地绝对路径由 Agent 内部传输记录解析；通用
`transfer-lifecycle` 路径、Web、远程来源和旧 Agent 均不得伪造可定位权限。
Agent IPC 用 `transfer-open-local` 能力声明启用入口，浏览器不获得磁盘访问能力。

上传在存在本地原文件时直接显示该文件。下载完成后显示本地目标文件；
下载进行中目标文件尚未提交时，仅打开已存在的目标父目录，
绝不把临时文件或不存在的路径假装成已保存文件。缺失或不可访问的路径返回可见错误。
文件路径不会作为右键命令参数传回 Agent。窗口关闭不取消任何传输。

此阶段不扩展到同步文件夹后台、FUSE 水合、ZIP/文件夹合并任务、
由浏览器接管的下载、以及外部生命周期管理的上传。均不显示不可用的入口。
