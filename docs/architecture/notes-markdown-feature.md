# xDrive 笔记：跨平台 Markdown 文件契约（2026-11-04）

## 已确认范围
「全部功能 → 笔记」正式入口：Web、PWA、Desktop、DSM、纯原生 iOS、纯原生 Android。两类笔记：「iOS 备份」严格只读（可查看/下载）、「我的笔记」支持新建、编辑、删除、Markdown 阅读与源编辑、图片插入、搜索、自动保存、版本历史。每个 Server Owner 完全隔离，无多人实时协作、默认无分享；文件页可见。保留移动端既有五模块及模块内导航，DSM 与 Desktop 共用 XDriveApp。

## 七项最终验收决策

1. **覆盖平台：** Web / PWA / Desktop / DSM / iOS / Android 全部具备可访问的 Notes 功能；iOS、Android 为原生页面，Desktop 与 DSM 复用共享 XDriveApp 页面和各自经过认证的 Host 传输。任一平台只有类型或占位入口不算实现。
2. **真实目录：** 每个 Owner 文件根下 `/@xDrive/@笔记`，包括 `iOS备份` 和 `我的笔记`；Files 可见。根、系统子目录及其文件均禁止通过普通 Files 写接口改名、移动、删除或覆写。
3. **Apple Notes 导入：** 快捷指令仅自动备份用户显式交付且可读取的标题/文本；完整 Markdown 与图片通过用户手动选择文件导入。不能宣称读取 Apple Notes 专用数据库或自动获取其全部富文本/图片。
4. **iOS 备份只读：** Notes 页及 Files 页均只能查看、预览、下载；不能编辑、改名、移动或删除。专用、经授权的 iOS 导入 API 是追加/更新备份的唯一例外，不构成用户可随意编辑备份的入口。
5. **更新、删除与历史：** 仅当相同 Owner 的快捷指令提交相同、可验证的稳定外部来源 ID 时，视为同一原始笔记；内容变化更新当前 Note 并保留 FileVersion；相同内容幂等；源端删除不删除备份。未携带稳定 ID 的两条同标题笔记、各次手动导入，不得自动合并。
6. **我的笔记：** 新建、编辑、删除、Markdown 预览、图片插入与显示、标题和正文搜索、停止输入后自动保存、乐观并发冲突提示、旧版本查看及下载；所有正式支持的平台均需真实 Host 传输，不得以静态 UI 代替。
7. **账户与导出：** 以经过 Server 验证的 xDrive Owner 隔离所有目录、笔记、图片和历史；暂不提供多人协作、自动公开分享，允许手动下载/导出。切换 Owner 必须清理前一个 Owner 的页面内容和在途结果。

## 统一真实文件目录
Owner 的文件根目录下：
- /@xDrive/@笔记/iOS备份 — iOS 文本与手动 Markdown/图片导入
- /@xDrive/@笔记/我的笔记 — 可编辑 Markdown
- 每个笔记以稳定 xDrive Note ID 组织一个正文 .md 和目录 _assets/<Note ID> 下不可变图片。

真实数据仍通过现有 Node、File、CAS 和 FileVersion 保存，而非容器宿主新建明文目录。目录 ID 必须通过 Server 绑定到 Owner，不能通过同名文件夹擅自获得权限。首次进入时显式初始化，既有冲突目录不自动接管。

普通文件接口可以显示、预览和下载，不能修改、删除、移动、重命名内置目录和里面的内容。保护必须在 Server，对所有普通写路径、UploadSession、批量/异步操作、Undo/Redo、回收站、历史版本、分享上传和同步落盘均成立。自己的笔记只允许走专用 Notes API 编辑，Apple Notes 备份无论通过什么客户端都只读。

## Notes API 与数据语义（验收契约）
稳定 Note 记录绑定 Owner、Note ID、source=ios_notes 或 mine、可验证的外部来源标识（如有）、Node ID、Revision、正文 SHA-256、附件目录。客户端不能擅自改 source。

苹果 Notes 没有第三方读取整个数据库的 API，快捷指令仅导入用户实际提供的文字。不能保证无损读取富文本、图片、表格、附件、锁定笔记；完整 Markdown 和图片采用用户手动导出/导入。若快捷指令未提供稳定 Notes ID，两个同标题源笔记不能被自动合并，标题重命名也不能声称能可靠追踪；缺失稳定 ID 时须保持独立快照或人工映射。

相同来源标识且内容相同：不重复上传。内容变更：保持同一 Note 可见项，旧版本存在 FileVersion。源端删除：不删除云端。任何旧版本仍引用的原始图片不得被回收。手写笔记自动保存以 expected_revision 乐观并发，409 时保留草稿，不能静默覆盖另一个设备。Markdown 渲染净化不安全 HTML，图片仅使用同 Owner 的授权相对资源路径；支持真实容量、读写权限、100k 分页与取消，不能无界加载。

Android 手动导入规则：用户一次选择一份 .md/.markdown 与正文明确引用的本地图片；最多 32 张图片、每张不超过 20 MiB。仅上传正文引用的图片；远程 URL、绝对路径、目录穿越、同名但来自不同目录的歧义引用均拒绝。图片上传走当前 Owner 专用 iOS 备份导入 API，使用一次性 manual-md: 会话标识完成同一条只读备份的创建与图片路径更新；不提供普通编辑、删除或自动重试。

适用 CI 与 Final Gate 均绿色、GitHub 无冲突且满足合并保护规则时才能合入 master；不以 master 单纯前进为理由重跑已经完成的有效 PR CI。正在运行或已验证通过的 PR 不重写 HEAD、不取消有效 CI；只有真实失败、兼容性或安全问题需要修复时才介入。iPhone/Android/DSM 真机行为没有实际执行必须记为「未验收」，不能以代码存在或 CI 通过替代。

同步备份任务的加密日志等非功能增强可以后置，但本文件明确要求的 Owner 隔离、受管目录只读、版本不丢失、写冲突不覆盖属于功能正确性，不得跳过。
