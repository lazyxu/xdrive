# iOS iPhone portrait/landscape page layouts and navigation acceptance (2026-10-30)

Status: approved product layout contract and implementation checklist; **not** proof of a shipped/physically validated IPA. The five-tab and L1/L2/L3 rules in [ios-native-navigation-and-gallery.md](./ios-native-navigation-and-gallery.md) are authoritative. This document narrows only the six requested iPhone page families. It must not create a second native/React UI or modify Android, Server or DSM.

## Shared viewport contract

- Fixed destinations: **全部 | 动态功能 | 图库 | 文件 | 我的**. Only the dynamic slot's icon/label may change. Opening Files/Gallery/Map/Viewer never consumes it; the Launcher has no back-to-launcher navigation stack.
- L1: compact native header and bottom navigation. Portrait bottom items show icon above label. Landscape items show icon beside short label; visible bar target height 44–50 pt **plus** the system bottom safe inset, with a minimum 44×44 pt accessible hit region. Do not install a side rail or second navigation strip. Native TabView may require UIKit-backed adaptation to guarantee this on physical iPhone: treat a static specification as not yet implemented.
- L2: hide the five-tab bar and reduce header chrome **only on an intentional focus transition**, not on rotation itself. Keep a visible “恢复导航” action respecting the top/side safe insets. Returning restores the same Owner-scoped module, map camera, Files path and selection.
- L3: a fullscreen native Viewer owns transient controls. A tap toggles them; close/back returns to the original Files or Gallery page and its valid anchor. Device rotation must not pop, change source tab or start a second media transfer.
- Calculate columns from **actual safe-area-adjusted content width**, not iOS size-class alone (landscape iPhones may still be compact). Never place tappable controls in the notch/Dynamic Island/home-indicator exclusion zones. Prefer vertical scroll and bounded content over clipping at larger accessibility text sizes.
- Keep only serializable non-secret route, sort/filter and coarse cursor/position if restoration is required; never persist credentials, signed preview URLs, PhotoKit local identifiers, raw local album memberships or stale Owner metadata. On Owner/Root/Server switch, session invalidation wins over visual restoration.
- Inactive pages may cancel disposable thumbnails, list reads and preview preloads. Manual/automatic durable upload and encrypted receipt review must not be canceled by tab switching, focus change or rotation. Permission revocation invalidates old content immediately.

The exact split threshold is a layout choice after real safe-area measurement, not a hardcoded rule tied to landscape orientation. No screen may rely on a third column simply because an iPhone rotates.

## Route-state and interruption examples

1. **全部 → 备份 → 文件 → 全部 → 存储 → 图库:** 动态显示“存储”; recent includes 存储 then 备份 (bounded list), each with a permission-checked resumable route. Files and Gallery maintain separate histories. No back button crosses these tabs.
2. **文件 → 图片 Viewer → 关闭:** return to Files, not to Gallery or 全部. **文件 → “在图库中查看”** explicitly selects Gallery and only its Gallery-local path; a failed PhotoAsset mapping shows a truthful unavailable message.
3. **全部 → 地图:** select Gallery then its map subroute; opening a map photo goes to Viewer, closing returns to the map camera/cluster. Rotation changes composition, not route identity.
4. **Owner A → B → A / Server switch:** purge parent tab state and all old Owner/Root-scoped child data and confirmation identity. A returning later is a new verified session; its old signed URLs, PhotoKit IDs and privileged pages must never replay.
5. **During backup or unknown ACK:** leaving the page/rotating cannot trigger duplicate uploads, erase or auto-retry unresolved receipts. The user can navigate while the independently owned durable task continues.

## Acceptance matrix and current engineering boundaries

- Check portrait **375/390 pt**, realistic landscape widths/heights including **844/852/899/900 pt**, left/right safe-area insets, dynamic island/notch and home indicator. Recheck on real iPhone, not only screenshots or size classes.
- Rotate with non-root Files path, Gallery album page/tile, selected map cluster, L3 photo zoom/video/Live, backup progress, and open/closed consent. Validate keyboard, VoiceOver, large Dynamic Type, light/dark themes, long-press recent picker and discoverable alternative.
- Test app kill/relaunch and Owner A→B→A, token expiry, offline/back online, PhotoKit Full/Limited/Denied and role revocation. Restored routes must be reauthorized and reread, not present stale frames.
- Current master has the native five-tab shell, local albums, Owner cloud originals, full-screen local/cloud Viewer and native backup controls. It does **not** yet have complete native Files, server Admin UI, full-library/1:1 map parity, or complete persistent per-feature nested route restoration. A compact landscape bar is implemented in source but still requires physical safe-area/VoiceOver acceptance.
- Gallery cloud PhotoAsset/adaptive grids are in separate iOS PR #3282; do not duplicate or rewrite its validated HEAD. Independent photo/Viewer safety work is in PR #3290; a failed check there is **not** validation of this layout. Keep branches independent until exact-head compatibility gates allow integration.
- Code/API/security tests and iPhoneOS unsigned IPA compilation are prerequisites to merge. SideStore, physical-rotation, real PhotoKit/iCloud/Live, A→B→A hardware and 100k stress are **跳过（未验收）** until evidenced.

## Implementation sequence (scope: native iOS only)

P0: reset parent navigation state on any Owner/Server/Root change; preserve feature-local stacks and durable backup ownership; integrate the actual dynamic recent picker/restore with strict scoped state. P1: adaptive Gallery/photo wall and compact one-row source navigation (reuse #3282), then implement L2 map/file focus and L3 return anchors. P1: landscape Files/backup/admin composition only when each native feature is backed by real authorized service APIs. Keep unreached features marked unavailable instead of rendering empty fake panes.

## 2026-10-31 scoped implementation: Gallery short-landscape header

- **Current code:** `NativePhotosDashboard` uses the actual safe-area-adjusted Gallery geometry: at width ≥680 pt, height <500 pt and non-accessibility Dynamic Type, the source chips and a 48×44-pt native backup status/shortcut occupy **one row**. The source list scrolls horizontally, and the backup shortcut retains explicit VoiceOver state (busy, uncertain-receipt pause, no PhotoKit permission, enabled/disabled).
- **Fallback:** narrow/portrait or accessibility text retains the existing full status row followed by horizontally scrollable source chips. Landscape does **not** imply L2, change selected tabs or remount the media wall. The existing custom bottom bar keeps its separate minimum 44-pt targets.
- **Unchanged:** five-tab order; Owner-bound cloud/local/gallery map routes; L3 Viewer; backup controller, original uploader, consent/ACK ledger and cancellation semantics. This change only compresses presentation in supported viewports, not background execution.
- **Validation:** existing iOS compact-bottom-bar source contract now checks safe-area geometry, large-text fallback and one owner of the Gallery source switch. Exact-HEAD iPhoneOS compile, associated CI/Final Gate and physical rotation/VoiceOver checks remain separate evidence.
