# 云端照片 OCR

OCR 在 xDrive Server 的 Photo Intelligence 宿主上执行。中文和英文识别结果跟随
当前 Owner、照片 Node 版本及内容指纹保存。图库搜索的 `q` 同时查询文件名、标签
和有效的 OCR 文字；网格列表不加载识别全文。

Web/PWA/桌面使用共享照片属性面板查看、选择、复制和刷新识别文字。
iOS 和 Android 使用原生照片信息面板，按需读取同一个
`GET /api/v1/media/items/{node_id}`。切换账号、关闭信息页或原生应用进入后台后，
旧面板不再接收结果。更新照片后，旧版本的文字不能显示或用于搜索。

## 首次部署及旧安装升级

托管安装器在启动 Server 前预置私有 Unix Socket、随机模型令牌及独立宿主应用令牌。
这一步不启动模型，也不更改自动分析策略。旧安装若这些配置为空，需要先通过
正常的服务器升级流程更新安装器、宿主管理器和 Server；仅保存模型“启用”不能
给已经运行且未构造分析客户端的旧 Server 动态补上连接。
共享模型容器默认内存上限为 2GB；旧安装显式保存的上限会保留。若仍为 1GB，
启用前应检查可用内存并调整 `XD_PHOTO_FACE_MEMORY_LIMIT`：真实完整模型自检在
1GB 限制下被 OOM 终止，在 2GB/1CPU 下通过。此值是容器上限，并非固定预留内存。

升级后，在“系统依赖 → 动物/物体识别与 OCR”管理共享 Photo Intelligence 宿主：

1. 保存启用配置，再提交应用。
2. 宿主确认固定模型容器不存在时，允许首次创建；Docker 无法查询仍视为未知。
3. 首次缺少镜像时先有界下载（最长 10 分钟），持续更新执行状态，再创建容器。
   已缓存镜像无需访问镜像仓库。下载或启动失败不会确认应用成功。
   启动后最多等待 120 秒，覆盖 Compose 的启动期与健康检查间隔；明确不健康即失败。
4. 检查宿主、独立模型 Info 和实际执行探针；然后检查全局自动分析策略中的
   物体/OCR 自动任务是否启用。

新照片在上传和媒体索引完成后进入现有 `photo.smart_search` 队列；现有未分析照片
使用同一自动扫描补齐。开启策略、任务入队和识别成功是三个不同状态。
原始 Docker Compose 安装仍须在 Server 启动前配置共享 Socket 和两种独立令牌，
参见 `deploy/.env.example`。令牌不得放进浏览器、原生客户端或诊断日志。

## 重试与验收

自动分析启用时，失败照片按现有服务端退避策略重试。原生“重新识别云端图库”
明确确认后调用 `POST /api/v1/photo-intelligence/reanalyze`，请求
`{"kinds":["smart_search"]}`。它重跑当前账号的全部云端照片的 OCR 和物体识别，
并非单张照片重试。Web/PWA/桌面沿用任务中心的同一入口。
只有收到 HTTP 202、匹配 Owner 和任务种类的确认后才提示入队；丢失确认不自动重复 POST。

测试应覆盖中文/英文结果、空结果、失败、过期版本、账号切换、取消、刷新和队列确认。
真实模型测试与模拟 HTTP/组件测试分别记录；完整 iOS 编译依赖 macOS/Xcode CI。
识别器固定为官方 PP-OCRv5 mobile ONNX；中文、英文已知文字 JPEG 同时用于
模型测试及私有 Socket → PostgreSQL → 图库文字搜索测试。模型替换更新流水线版本，
由现有分析调度重建旧结果。测试样图通过不代表任意字体、模糊照片都能准确识别。
服务器代码通过测试不代表 192.168.2.4 已部署，也不代表手机已安装或完成实机验收。
