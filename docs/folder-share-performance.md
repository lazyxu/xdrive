## Feature and security contract

- Owner creates/lists/revokes File or non-root Folder shares. Existing legacy file share API stays compatible; new authenticated /nodes/:id/shares endpoints take either Node type.
- Existing 256-bit bearer capability is stored as SHA-256 only. Optional password is bcrypt-verified on each page/ticket request. Expiry, disabled Owner, revocation and total signed file-download-ticket count remain enforced. A folder share cannot implicitly expose the account root.
- Public metadata advertises dir/file type but never enumerates children until a POST with bearer token and, when configured, password. Neither passwords nor storage keys enter share URLs. All views are read-only, with no mutating APIs or upload/sync/delete delegated.
- Each folder page performs a bounded owner-scoped active-ancestor check (max 128 parents), a keyset Node ID read capped at **100 results plus one has-more probe**, and a single batched File-size preload. No recursive COUNT, eager thumbnail requests, automatic ZIP or archive scan of 100k descendants.
- Every descendant file download consumes one grant of the share's total download allowance, and gets a short-lived signed download ticket. On ticket issue and stream, verify current Owner, current file revision and active ancestor scope; moving/removing a file from the subtree invalidates an issued ticket. Existing single-file downloads retain their path.
- Obsolete public folder-page reads are aborted immediately by AbortController. The endpoint uses Request.Context and database WithContext so the Go work can stop; durable user-initiated downloads are not silently aborted on viewport navigation.
