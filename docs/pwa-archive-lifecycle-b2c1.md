# PWA P0-B2c1：历史静态资源只读容量审计（不自动清理）

2026-10-21。P0-B2c1 是历史 JS/CSS 生命周期安全管理的首个增量，处于 Draft。上游 #2271/#2273 仍需分别通过新准确 HEAD 完整 CI 再合入。本任务不改变任何产品运行时热路径。

## 使用

在已获授权的服务器本机，显式指定公开哈希资产归档根目录（Caddy XD_CADDY_ASSET_DIR）。不默认扫描目录，不请求生产账号或任何私密数据：

```sh
node scripts/pwa-archive-audit.mjs "$XD_CADDY_ASSET_DIR"
node --test desktop/tests/pwa-archive-audit.cjs
```

返回单行聚合 JSON：文件数、目录数、逻辑字节数、按 dev+ino 去除硬链接重复的字节数、平台可用时的 stat.blocks×512 分配量及文件类型统计。未提供物理块统计的平台返回 null，不臆造。它不是实际磁盘配额、压缩节省、活跃客户端计数或一致性快照；归档持续写入时结果仅供参考。

## 安全边界

- 只接受明确的目录参数。与正式 deploy/pwa-archive-assets.sh 一致，仅允许公开内容哈希 Vite 资源的 js/css/svg/png/webp/woff/woff2/jpg/jpeg/gif/avif/wasm 扩展名以及安全子目录。符号链接、非普通文件、非哈希资源、可能属于私密 API/JWT/媒体内容的文件使审计直接失败。
- 不读取文件内容，不发出网络请求，不修改、搬移、覆盖或删除文件；错误消息不包含操作员的文件名、目录和数据。
- 独立 Node22 回归测试包括空档案、双版本哈希、硬链接去重、真实历史发布器反复 seed 的幂等、符号链接/私密路径拒绝、元数据与字节未修改。专项 GitHub Actions 通过完整可复核源码运行。

## 为什么暂不执行自动 GC

历史 JS/CSS 是否能删除，取决于旧 HTML 对动态 chunk 的引用、离线安装的 SW/controller 生命周期、尚未完成上传、长期未打开的 iPhone 主屏客户端和回滚窗口。当前没有可信的活跃版本引用闭环；不设猜测性的 7/30 天自动删除窗口。正式 deploy/pwa-archive-assets.sh 保持只追加发布，旧文件继续保留。B2c2 必须有真实多版本浏览器/回滚测试及安全策略才可能讨论清理。

## 诚实的验收口径与后续

这是之前不存在的只读容量统计能力；BEFORE=不支持，不能写成 0ms。暂不声称节约了任何用户磁盘容量、提高 iOS PWA 启动速度或者改善 100k Gallery FCP/p50/p95。P0-C 仍须相同设备、同样素材和网络条件先测 baseline→仅必要时优化→同条件复测；随后才进入 P1 用户明确授权的只读 IndexedDB 快照与 P2 限量缩略图缓存，不预缓存全量图库。

按用户长期约束，无法访问的生产环境安全验收标注“按用户决定跳过（未验收）”，不得索要生产 AK、Cookie、JWT、HAR、凭证或人工验收，也不能阻塞源码 CI/PR。源码权限/隐私/安全负例继续执行。
