# iOS 云端备份原件列表连续滚动（2026-11-03）

## 范围

仅修改 iOS 原生云端备份原件列表的**可见翻页交互**，不改变 Owner 根目录 REST 读取、48 条后台扫描、原件 Viewer、原件恢复、去重、缩略图、备份账本及其他平台。独立于本机照片 PR #3670 和云端 PhotoAsset PR #3680，不改这些正在排队 CI 的 PR HEAD。

## 交互

- 删除“继续检查下一批”按钮；用户滚动到已加载照片末尾时自动检索后续 Server 目录范围。
- 因云端根目录包含与 iPhone 备份无关的文件，有的 48 条范围没有任何备份原件。空范围最多自动连续扫描 4 批，防止在短屏幕上无休止爬取百万条无关文件；下一次向下滑动可继续一个有界扫描窗口，不显示上一页/下一页。
- 只在场景 active、当前 Owner 存在、无 Viewer、无正在读取任务且没有失败时启动下一批；基于 scanned offset 去重重复的 onAppear 触发。
- 对新增文件导致 offset 重叠继续沿用 seenNodeIDs 去重；真正的服务器扫描进度使用 scanned，不能把已筛选出的备份照片数冒充根目录扫描总数。
- Owner 切换、失效、网络失败、Reader 版本和原件 Viewer 仍保留原有隔离与重试；只有显示中的缩略图才请求服务器派生图，不暗中下载原件。

## 验收

更新原有 ios-native-cloud-original-thumbnail-wall.cjs 源码测试（已在 iOS Native Unsigned IPA 专项中运行），增加连续滚动、尾部触发、空范围有界扫描、滑动再次授权、Viewer 停止读取、旧 Owner 撤销、48 条真实 offset 前进等断言。准确 HEAD 的 IPA、适用 CI、Final Gate 和 GitHub 保护条件都通过后才允许合入 master；真机短横屏、100k 根目录、长距离滚动、性能/OOM 仍需单独验证。

注意：既有模型保留已找到备份原件的轻量元数据，虽缩略图可见时才缓存，但超大规模根目录仍有进一步虚拟化空间；不得冒称已达到 Apple Photos 的全部性能与布局一致性。
