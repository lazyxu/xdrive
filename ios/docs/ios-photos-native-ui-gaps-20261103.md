# iOS 原生相册列表与 Apple 照片 App 对齐清单 — 2026-11-03

## 验收原则
以当前 iPhone 照片 App 的共同行为为界面基线：照片/视频/Live Photo 不标注文件名；所有可见相簿目录、照片墙、云端图库都应滚动连续。底层可批量读取和虚拟化，但不可显示“第 N 页”或要求用户按“下一页”。xDrive 的“本机/云端/备份”能力可以扩展，不用为模仿 Apple 删掉自己的功能。**静态代码实现不等于 iPhone 真机像素级验收。**

## 本 PR 改动
- [x] 本机图库移除“连续/分页”切换、旧分页墙不再挂载；保留全库日期索引和 64 项窗口元数据扫描。
- [x] 本机连续照片墙移除“当前照片页”“第 N 组”等人为分页文案。
- [x] 本机相簿目录改为有封面、名称、数量的双列/自适应连续网格，后续 32 项滚动自动接续；重入时按当前授权快照恢复先前 32 项数值锚点（不持久保存相簿 ID），封面在可见时请求。
- [x] 相簿成员页移除上一页/下一页，改用与本机图库相同的 1:1 缩略图、64 项虚拟照片墙和 Viewer 边界读取，权限/相簿变更令视图失效。
- [x] 「添加到相簿」目的地选择器取消上一页/下一页与页码，向下滚动自动读取后续 32 个已授权相簿；保持创建/重命名/删除及成员增删原有 PhotoKit 验证。
- [x] 保留多选、PhotoKit 收藏/删除、原件分享、Viewer 跨页及返回、短横屏/VoiceOver 基础兼容代码；写操作继续严格复核当前 64 项的身份，不能因连续滚动扩大原件操作范围。
- [ ] iOS IPA 编译、专项测试、Final Gate、真机照片权限/iCloud/100k 大库触控验收：必须由准确 PR HEAD 的任务另行确认。

## 范围边界与 PR 守则
仅修改 iOS 本机照片/相簿列表入口与配套源码契约测试；不修改地图、Android、Web、备份写入器、Server/Owner API；保留已合入 master 的 #3659 相簿管理和本机照片搜索能力。所有代码变更单提交进入独立 PR，待 IPA/适用 CI/Final Gate 与合并条件通过后才允许合入 master。

## 专项验收用例
1. 0/1/31/32/33/64/65/128 个相簿/媒体边界，不出现页码/“下一页”，滚动不重复、不漏图。
2. 1 万/10 万照片：首次只加载可见虚拟页、远离视口释放缩略图和元数据，不下载 iCloud 原图；快速向前/向后滚动位置稳定。
3. 选择任一张照片 → Viewer 向前/向后跨 64 位置 → 返回相簿，定位到同一 ID、拍摄/修改时间匹配的网格。
4. 在读取中新增/删除相簿、变更成员、撤销照片授权、Limited→Denied、切后台，所有过期图片立即不可见、批量操作不得误操作其他照片。
5. iPhone 375/390pt、横屏短高、深浅色、动态文字、VoiceOver、弱网络和 iCloud 本地未下载状态。
