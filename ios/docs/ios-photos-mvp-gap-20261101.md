# xDrive iOS 原生图库 MVP 缺口盘点（2026-11-01）

基线：master `52edf7f41011452c3ffabbeb3c082c618bb0c92a`。以 `ios/XDriveIOS/` 实际 SwiftUI/PhotoKit 源码为准，不把已提交代码等同于真机验收，也不把“读过一个分页”当成“已完成全库备份”。

产品目标：以 iOS 照片 App 的**日常浏览、查看、选择、整理**为交互基线，再附加 xDrive 备份状态、云端 PhotoAsset 和原件恢复。iOS 继续使用原生 SwiftUI/UIKit，固定五个底部模块「全部｜动态功能｜图库｜文件｜我的」。

## A. 当前已有的可复用基础（不是完整 Photos 对齐）

- [x] 原生入口 `XDriveIOSApp.swift`、Owner 登录、五模块导航、Gallery 子来源和独立返回。
- [x] PhotoKit 当前授权子集读取（包括 Limited），64-slot 有界分页、缩略图、Library 变化失效、系统相册目录和成员页。
- [x] 本机照片/视频/Live Photo Viewer；静态缩放、同页前后项、返回当前网格锚点。
- [x] Server Owner PhotoAsset 的 48-item 云端分页、搜索、相册、缩略图及受限的照片/视频/Live Viewer。
- [x] iOS 备份根目录的 `-xios-` 原件列表和 Viewer，包括经验证的 Live ZIP 双资源播放。
- [x] 原件备份基础：手动、前台自动增量、可选 BGProcessing、Live 资源打包、可信收据、暂停核对、加密账本；当前每次最多检查 256、确认新增 20。
- [x] 本机 MapKit + 云端 Owner 地图基础存在，但单图库入口接通云端地图仍在 PR #3479。

## D. 明确不作为本轮 MVP 功能门槛

代码级数据正确性（不能误判收据或导入错 Owner）仍需要。高级隐私/安全审计、100k/115k 压测、完整辅助功能审计、复杂照片权限策略、真实 iPhone/SideStore/iCloud 现场验收可另列，不能虚称通过。本轮以适用源码测试、Xcode 无签名 IPA 编译、最新 PR HEAD CI 和 Final Gate 为合入依据。

## E. 本次实现的界限

PR `feat/ios-photos-cloud-original-restore-20261101` 仅补「云端**备份原件** → iPhone 系统照片」单项：在当前 Owner 的 L3 原件 Viewer 中点击「保存到 iOS 照片」，显式请求 add-only 权限；图片、视频下载文件原件，Live ZIP 复用验证通过的 still/MOV；离开当前 Viewer/切换 Owner 时取消未提交请求；临时数据清理；结果反馈。**不是**自动全库恢复，不是 PhotoAsset 全云端写回，也不修改既有上传器、账本和收据。
