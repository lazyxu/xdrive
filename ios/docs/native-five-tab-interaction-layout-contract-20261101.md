# xDrive iOS 原生五入口导航与横竖屏布局验收规范（2026-11-01）

> 状态：**产品交互规则冻结，实施进度按实际源码和 PR 单独验收**。本文件描述目标行为，不声明所有条目已实现。
> 范围：iOS 原生 SwiftUI/UIKit 工作区、其页面展示状态与交互；不重做总体布局，不修改 Web/PWA/Android/Desktop/DSM，不变更服务器 API、备份写入器或权限边界。

## 1. 架构与导航归属（冻结）

- 底部始终保留五个**槽位**，顺序：**全部｜动态功能｜图库｜文件｜我的**。动态槽位显示当前功能图标及名称，但槽位归属永远为 dynamic。
- 每个固定模块单独维护 NavigationStack。左上返回只回退**当前模块内部**；不得把其他模块压入当前返回栈。
- 「全部」只作为功能启动台，不保留单独深层返回历史。选择功能时切换目标 Tab；返回启动台靠点击「全部」，不是跨模块 Back。
- 「图库」容纳本机照片、相册、云端图库、备份原件、**本机/云端照片地图**；从启动台打开地图直接选择 gallery/map，不占动态槽位。
- 「文件」打开文件 Viewer 属于文件来源内部的 L3 覆盖层；「在图库中查看」属于有身份映射时才允许的跨模块动作，需要切换到 gallery 并重新定位已授权 PhotoAsset。
- 「动态功能」承载非固定功能（备份、同步、存储、传输任务、设备、诊断等）。选择另一个动态功能是**替换当前槽位内容**，不能把新功能压入旧功能的返回栈。
- 「我的」承载当前用户、服务器连接和 iPhone 本机设置；服务器管理员功能属于「全部」中的受权限保护入口，绝不因本机有管理员菜单就假定 Server 已授权。
- 全部入口必须保持原生界面。未实现的目标显示明确不可用，不模拟任务进度、权限、持久数据或上传完成。

### 必须遵守的目标归属

| 动作 | 目标位置 | 返回行为 |
| --- | --- | --- |
| 全部 → 文件 | files | 文件内回退；不返回启动台 |
| 全部 → 本机/云端照片/地图 | gallery + 相应来源 | 图库内回退；不返回启动台 |
| 全部 → 备份/同步/存储/诊断 | dynamic + 功能 ID | 功能内部回退；从全部重新选择 |
| 文件 → 图片/PDF/视频 Viewer | files + L3 overlay | 关闭回原文件夹或搜索页 |
| 图库/地图 → 照片 Viewer | gallery + L3 overlay | 关闭回相同图库来源、地图视窗或结果页 |
| 文件 → 在图库中查看 | gallery + 重新授权定位 | 直接切 Gallery；不混合 Files Back 栈 |
| 图库 → 备份设置 | dynamic + backup | 切 dynamic；图库既有状态保留 |
| 备份 → 查看云端备份原件 | gallery + originals | 切 Gallery；后台任务不受影响 |
| 深链 → 指定模块 | 先验证 Owner/Root/能力，再切目标 Tab | 禁止跨模块历史栈和旧 Owner 复用 |

## 2. 动态功能最近历史与状态恢复（P0）

- 最近使用的**非固定功能**采用去重 MRU，最多 6 个；选择旧功能时将其移至首位，长按动态 Tab 和「全部」最近使用均可恢复。
- 目标恢复粒度为：已实现功能 ID、该功能允许恢复的子路由、筛选/排序、分页/滚动锚点、专注状态（仅适合恢复且经授权者）。不无限驻留 SwiftUI 实例，不保留历史 View 树或耗尽内存。
- 恢复仅保存**提示信息**，不能把存储快照当作 Server/PhotoKit 访问凭证。Owner 根作用域必须验证 origin + server instance + owner + root；跨服务器、退出、权限变化、Owner A→B→A 必须清空前一身份的页面位置并重新查询。
- 持久字段应使用版本化、白名单、大小上限与有界深度。不能存放密码、Token、Cookie、上传收据、签名媒体 URL、PhotoKit 本地资产 ID、照片 GPS、预览票据或未验证的文件身份。
- 服务器文件路径/Node 定位在恢复时必须重新验证当前 Owner 与节点可见性；查不到时退回上一个有效父目录或该模块根页，不能显示旧 Owner 内容。
- 文件过滤器、图库来源和分页位置可以作为非权威提示；**精确地图视窗与 Viewer 正在展示的媒体身份只承诺在当前进程/同一授权会话内保持**。冷启动时重新验证，无法验证则回所属页面，不自动打开旧媒体。
- 对于当前尚未实现的原生动态模块，不持久化一个无法恢复的“成功页面”；可以在启动台列出「未接入」，但不能伪造继续运行的业务页面。
- 前台页面切换应撤销无用的缩略图、列表分页和预览读请求；独立持久化的上传/备份/同步不得仅因 Tab 切换或布局旋转被取消。退出登录、明确取消和授权撤销按原有 Owner 边界处理。

**master 现状：** \`NativeNavigationRouteStore.swift\` 的 v1 有 Owner-scoped snapshot、gallery/map/local-album 的有界偏移，但 activeDynamic/recentDynamic 仅接受已实现的 backup；每个动态功能的深层恢复、Files 完整路径恢复和动态 MRU 持久化仍是待实现目标。不得把目标写成已完成。

## 3. L1/L2/L3 显示等级（P0）

| 级别 | 顶部 | 底部五入口 | 返回/恢复 |
| --- | --- | --- | --- |
| L1 标准 | 标准标题与模块内 Back | 显示 | 当前模块独立路由 |
| L2 专注 | 精简标题/工具条，保留显式「显示底部导航」 | 隐藏 | 恢复 L1 后仍停留原功能/同一位置 |
| L3 Viewer | 内容全屏；单击切换顶/底操作控件 | 始终隐藏 | 关闭覆盖层，返回创建 Viewer 的模块和锚点 |

- L2 属于**显式的功能状态**，不是「检测到横屏」就自动进入的布局。地图以 L2 为目标进入体验；文件多栏、大图表、日志可以按需要主动进入 L2。导航恢复按钮不得只依赖不可发现的手势。
- L2 → Viewer → L2 应保留已授权的来源、焦点和相机/滚动锚点；不额外生成一层跨模块 Back。
- L3 的单击显示/隐藏控件不得吞掉双击缩放、捏合、平移、Live Photo 长按等内容手势；视频交互使用媒体播放控制优先。PDF 只读，不引入编辑模式。
- 屏幕旋转不修改 L 等级，L2/L3 退出靠明确动作。切换不同 Tab/图库来源时，非当前来源的专注状态应按页面策略退出，不得残留不可恢复的隐藏底栏。
- 弱网、401/403、权限撤销必须明确反馈；Viewer 或地图不可在失去 Owner 后继续显示旧账户数据。

## 4. 横竖屏内容布局（P1）

所有阈值使用**实际可用 safe-area 宽高（pt）**，不是设备型号。辅助功能大字体或空间不足时退回单列，关键操作永不因压缩而不可触达。

| 页面 | 竖屏 | 横屏 | 状态/交互边界 |
| --- | --- | --- | --- |
| 五入口底栏 | 图标上文字下；视觉 56pt | 图标左文字右；视觉 48pt | 交互高度至少 44pt；系统底部安全区另算；L2/L3 隐藏 |
| 全部 | 搜索 + 最近 + 常用 + 分类自适应网格 | 增加网格列数、缩短静态说明，不另建九宫格首页 | 固定入口不建返回历史；收藏是明确用户偏好，不能冒充已实现 |
| 文件 | 路径/搜索/排序 + 单列列表，文件夹逐级返回 | 默认仍 L1：紧凑搜索/排序 + 扩宽列表；**主动打开多栏**时才进入 L2，建议宽≥760pt 且高≥320pt 后试两栏 | 搜索、排序、路径和 Viewer 返回锚点不因旋转重置；多栏控制应在受限尺寸退回单列 |
| 图库 | 来源切换、状态信息、按最小触控目标自适应照片网格 | 宽≥680pt 且高<500pt、普通字体时，来源与备份快捷入口合并一行；照片网格增加可见列 | 网格与 Viewer 的数据 Owner 保持，旋转只重排；限定 PhotoKit 授权时继续明确展示 |
| 照片地图 | 地图优先，覆盖式必要控制与相册式聚合浮层 | L2 全宽地图；顶部紧凑本机/云端来源、地图/列表与恢复按钮；不设永久底部照片条 | 相机/选区只在当前授权会话复用；移动中保留可见封面但旧聚合不可冒充新授权；回 Viewer 复位原视窗 |
| Viewer（照片/视频/Live/PDF） | L3 全屏，单击可显隐控制；内容适配安全区 | L3 全屏，以可显示图像/视频/PDF 内容为主，控件按需浮层 | 关闭回所属模块；旧列表预读退让；不自动恢复跨 Owner 的媒体 |
| 相册备份 | 一列可滚动 Form：来源、手动、自动、后台授权、收据和结果 | 宽≥760pt 且高<500pt、普通字体时，状态/收据在左48%，设置/操作在右52%，两栏分别滚动 | 旋转不重新确认、上传或停止任务；所有二次确认锁定当前 Owner |
| 管理员 | 已授权后按功能列表 → 详情 | 实现后空间足够时可左目录、右详情；不足时单列 | 保持 L1；未拿到实时 Server 管理权限不显示入口；权限变更立刻失效 |

布局可以先实施和验收单列 + 横屏紧凑模式；文件多栏、管理员双栏须等真实 native controller 存在才接线。不要以模拟数据提前标记 MVP。

## 5. 必须通过的交互验收矩阵

| 场景 | 预期 |
| --- | --- |
| 全部→备份→文件→全部→存储→图库 | dynamic 显示存储；备份留在最近功能；文件与图库各自保留可恢复位置；未接入存储明确展示不可用 |
| 文件打开 Viewer，旋转后关闭 | 返回原 Files 列表/搜索及仍有效的 Node 锚点，保留排序和路径 |
| 图库打开地图→聚合→Viewer→返回→旋转 | 回图库地图，同源同相机；不把 local/cloud 两种身份与状态混合 |
| 地图在 L2，旋转后按「显示底部导航」 | 回到地图 L1，完整五入口恢复，地图数据不重新声明已授权 |
| 动态功能 A→B→A | A 的已实现子路由和白名单筛选提示可重建；无持久存活的 A View 实例要求 |
| 点击跨模块快捷方式 | 目标 Tab 正确、来源 Tab 状态保留、Back 只在目标模块内生效 |
| 执行备份时切文件/Viewer/旋转 | 持久任务和收据连续；仅无用前台读取消 |
| App 冷启动 / Owner A→B→A / Token 失效 | 只有经当前 Server/Root/权限重新验证的提示可恢复，旧账户的数据立即不可见 |
| 横屏刘海/灵动岛 + Home 指示器 | 关键操作不被安全区遮挡，五入口可达且点击目标≥44pt |
| Dynamic Type/VoiceOver/深浅色/长按动态 Tab | 单列回退，最近功能替代入口可达，焦点和按钮语义明确 |
| 服务器断连 / 管理权限撤销 | 可见错误与重试，管理员内容关闭，禁止旧 Owner 信息与任务结果冒充成功 |

测试视口至少覆盖 375/390pt 竖屏，以及代表性 844/852/932pt 横屏（实际 safe-area 可用值应在运行时取）。再做小高度、大字体、横竖反复旋转、弱网、后台回收、100k 列表的针对性回归。

## 6. 与现有实现/PR 的衔接和工作顺序

已存在的实现，不要重复建设：
- \`NativePhotosDashboard.swift\`：原生五 Tab、独立 NavigationStack、长按最近功能入口、Launcher 搜索/分类、48/56pt bar、Gallery 切换。
- \`NativeNavigationRouteStore.swift\`：Owner-scoped v1 路由提示，图库/地图/本机相册偏移；只对真实 backup 动态功能作冷启动恢复。
- \`NativeFocusVisibilityPolicy.swift\` 和原生地图页：目前部分图库来源具备可恢复的 L2 专注。
- \`NativePhotoBackupScreen.swift\`：横屏 48:52 双 Form；\`NativeLocalPhotoGallery.swift\`、\`NativeCloudOriginalGallery.swift\`：局部短横屏与 Viewer 来源锚点。
- PR #3479：同一图库地图入口整合本机和云端地图；PR #3473：Files CRUD、可取消传输与当前页批量删除。**这两条已有 CI 启动，不为文档整合、更新 HEAD 或重跑**。

待实施（依赖真实能力，不以规范文档冒充完成）：
1. **P0：** 路由切换与 Owner 作用域的真实跨模块深链；动态功能 per-feature memento 及退出/恢复策略；地图默认 L2/可恢复 L1 与 Viewer L3 控件一致性。
2. **P0：** 等 #3479、#3473 验证后基于其最终源码对地图/文件执行专项集成回归；不直接叠加到正在测试的 HEAD。
3. **P1：** 文件自愿多栏、地图横屏控制条、Viewer 显隐/返回锚点、Launcher 收藏与真实任务角标/任务中心。
4. **P1：** Server 管理员经权限核验后开放真实原生页面，随后做横屏双栏布局。未接入时仍保持隐藏。

本规范只冻结交互合同，不改变现有业务代码、后台写入行为、权限模型或 CI 配置。功能改动须另经独立/相关 PR 的精确 HEAD CI、iOS IPA 编译、Final Gate；所有修改经 PR 验证后方可合入 master。真机横屏/旋转、SideStore、VoiceOver 及生产权限切换的实际验收为：**跳过（未验收）**，不能用文档或源码静态检查代替。
